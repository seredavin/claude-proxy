## Context

Мотивация — в proposal.md, требования — в `specs/plain-listener/spec.md`.

Текущее устройство, от которого отталкиваемся:

- `config.TLSSource` — три значения (`auto`, `files`, `self`), каждое со
  своей веткой в `Config.validate()` (`internal/config/config.go`).
- `tlsconf.New()` возвращает `Provider` с обязательным `TLSConfig`; для
  `auto` ещё `HTTPHandler`/`HTTPAddr` под HTTP-01.
- `server.Run()` всегда строит `http.Server{TLSConfig: provider.TLSConfig}`
  и вызывает `ServeTLS(ln, "", "")`; ACME-слушатель поднимается, если
  `provider.HTTPHandler != nil`.
- `clientenv.baseURL()` всегда пишет `https://` и берёт хост из
  `cfg.Domain` (или заглушку `<имя-шлюза>`).
- `service.waitHealthy()` стучится на `https://` с
  `InsecureSkipVerify` и SNI из `Domain`.
- `gateway` от входящего TLS не зависит: `r.TLS` нигде не читается,
  `X-Forwarded-*` вычищаются.

## Goals / Non-Goals

**Goals:**

- Минимальная точечная правка: новое значение `TLSSource`, одна новая
  проверка в `validate()`, обход TLS в `server.Run()`.
- Невозможно случайно открыть plain-слушатель наружу — отказ на старте, а
  не предупреждение.
- Ни одно существующее значение `--tls` и ни одна существующая проверка не
  меняют поведения.

**Non-Goals:**

- Plain-апстрим (`--upstream http://`). Схема апстрима остаётся `https`.
- Unix-сокет как слушатель — отдельная идея, здесь не рассматривается.
- Изменение `chain-smoke.sh` под macOS: скрипт по-прежнему Linux-only
  (доверие между звеньями через `SSL_CERT_FILE`); добавить в него
  plain-звено можно, но это не цель изменения.

## Decisions

### D1. Четвёртое значение `--tls none`, а не отдельный флаг

Согласовано с пользователем. `--tls` уже отвечает на вопрос «откуда
сертификат»; «ниоткуда» — естественный ответ в том же ряду. Одна таблица в
документации, одна переменная `CLAUDE_PROXY_TLS` в `EnvironmentFile`.

Альтернатива — булев `--plain`: заметнее в командной строке, но два флага
про одно и то же и вопрос приоритета при `--plain --tls self`.

### D2. Loopback-проверка в `Config.validate()`, а не при `net.Listen`

Проверка по строке `--listen`: хост через `net.SplitHostPort`, затем либо
`strings.EqualFold(host, "localhost")`, либо `net.ParseIP(host).IsLoopback()`.
Пустой хост (`:9443`) — отказ: это все интерфейсы.

Почему не на уровне сокета: `validate()` — единственное место, где шлюз
отказывается от небезопасных комбинаций (пустые токены, `--upstream-key` при
дефолтном апстриме, перепутанные ключи). Проверка там же читается как
политика, тестируется табличным тестом без сети, и `install` получает отказ
до записи юнита.

`localhost` принимается по имени, а не по резолву: резолвить в `validate()`
— зависимость от DNS в чистой функции; а `localhost` в `/etc/hosts` на
что-то не-loopback — экзотика, которую сознательно не покрываем.

### D3. `tlsconf.New()` возвращает провайдер с `TLSConfig == nil`

Для `none` `New()` отдаёт `&Provider{Description: "без TLS (loopback)"}`.
`server.Run()` ветвится по `provider.TLSConfig == nil`: `Serve(ln)` вместо
`ServeTLS`. ACME-ветка сама не сработает — `HTTPHandler` пуст.

Альтернатива — ветвиться в `server.Run()` по `cfg.TLS == config.TLSNone` и
не звать `tlsconf.New()` вовсе. Отвергнуто: тогда решение «есть ли TLS»
размазано по двум пакетам, а `Description` для стартового лога пришлось бы
собирать в сервере.

### D4. `clientenv.baseURL()`: схема и хост зависят от `cfg.TLS`

Для `none` — `http://` + хост из `--listen` (он гарантированно loopback и
конкретен) + порт. `cfg.Domain` не используется: в этом режиме он
игнорируется и в остальном коде. Для остальных источников поведение
прежнее.

### D5. `--domain` при `none` игнорируется молча

Не ошибка: оператор может переключить `CLAUDE_PROXY_TLS` с `self` на `none`
в том же `EnvironmentFile`, не вычищая соседние строки. Не предупреждение:
`--domain` ни на что не влияет, и лишняя строка в логе на каждом старте
шумит без пользы. `--state-dir` тоже не требуется, но если задан —
`install` по-прежнему создаёт каталог (это безвредно и упрощает обратный
переход на `self`).

### D6. `install` поддерживает `none`

`waitHealthy()` получает признак TLS и для `none` ходит на
`http://127.0.0.1:<port>/healthz` без SNI и `TLSClientConfig`. Отказывать в
`install` не стали: на Linux-рабочей станции plain-звено под systemd —
законный сценарий, а половинчатая поддержка («run умеет, install нет»)
хуже пяти строк кода.

### D7. Стартовый лог

Существующее поле `"tls"` в записи «шлюз запущен» получает
`Description` провайдера — `без TLS (только loopback)`. Отдельного
предупреждения уровня Warn не добавляем: адрес и так loopback, угрозы нет,
а Warn при каждом штатном старте обесценивает уровень.

## Risks / Trade-offs

- [Оператор ожидает, что `none` пустит его и на `0.0.0.0` «для докера»] →
  Отказ с явным текстом ошибки и абзац в документации, почему так: в
  контейнерной сети токены подписки шли бы открытым текстом; для этого есть
  `self` + `NODE_EXTRA_CA_CERTS`.
- [`localhost` резолвится не в loopback из-за правки `/etc/hosts`] →
  Сознательно не покрываем (D2); риск маргинальный, а лечение — DNS в
  валидации — дороже.
- [Claude Code отказывается от `http://` в `ANTHROPIC_BASE_URL`] → Node SDK
  и CLI принимают `http://` (так работают локальные LiteLLM/прокси-заглушки).
  Проверить на стенде в рамках задач; если сломается — это блокер всего
  изменения, узнать нужно до документации.
- [`readHeaderTimeout`/`idleTimeout` подобраны под TLS] → Для plain
  ничего не меняется: таймауты про заголовки и простой, не про рукопожатие.

## Migration Plan

Новое значение, дефолт `auto` не трогается — обновление бинаря ничего не
меняет для существующих установок. Откат — вернуть прежний бинарь; конфиг
с `CLAUDE_PROXY_TLS=none` на нём не стартует с понятной ошибкой
«недопустимый источник сертификата».
