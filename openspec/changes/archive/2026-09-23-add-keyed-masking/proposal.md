## Why

Одинаковость суррогатов сейчас держится только на таблице в памяти
процесса: суррогаты IP и хостов выбираются случайно (`crypto/rand`,
счётчик `host-N`). После перезапуска шлюза, при `claude --resume` через
новый `claude-proxy local`, в параллельных процессах `local` и на разных
звеньях цепочки один и тот же адрес получает разные суррогаты. Модель
видит одну и ту же инфраструктуру под разными именами, кэш промптов
теряется, а сопоставить трассы разных запусков нельзя. Кроме того,
суррогат нельзя расшифровать без живого процесса: таблица умирает вместе
с ним.

## What Changes

- Новый ключ маскирования: файл с секретом (`--mask-key-file`,
  `CLAUDE_PROXY_MASK_KEY_FILE`). С ключом суррогаты IP-адресов и имён
  хостов вычисляются из значения и ключа, а не выбираются случайно: одно
  значение при одном ключе даёт один и тот же суррогат в любом процессе,
  после перезапуска и на любом звене.
- Вычисление обратимо только с ключом: суррогаты приватных IP и имён
  хостов — это шифрование с сохранением формата, и тот, у кого есть ключ,
  восстанавливает исходное значение без таблицы. Без ключа суррогат
  вычислительно не отличим от случайного.
- Формат суррогатов с ключом:
  - приватные IPv4 и ULA IPv6 — адрес того же приватного диапазона;
    адреса одной `/24` (`/64`) по-прежнему попадают в одну суррогатную
    `/24` (`/64`);
  - публичные IPv4 — адрес из `100.64.0.0/10` вместо документационных
    сетей (**меняется** вид суррогата при заданном ключе);
  - публичные IPv6 — адрес из `2001:db8::/32`, как сейчас;
  - имена хостов — `host-<шифртекст>.example` вместо `host-N.example`
    (**меняется** вид суррогата при заданном ключе; суррогат длиннее).
- Публичные адреса в пул суррогатов биективно не помещаются: для них
  вычисление детерминировано, но при коллизии сетей разрешается пробами
  по таблице процесса, а офлайн-расшифровка не гарантируется.
- Новая команда `claude-proxy gen-mask-key` печатает свежий ключ.
- Файл ключа проверяется на старте: формат и права (не доступен группе и
  остальным); ошибка — отказ стартовать.
- Таблицы остаются: они по-прежнему раздельны по метке токена и остаются
  единственным источником обратной подстановки в ответах — шлюз не
  «расшифровывает» наугад адреса, которые модель придумала сама.
- Без ключа поведение прежнее, байт в байт.
- `install` переносит `CLAUDE_PROXY_MASK_KEY_FILE` в `EnvironmentFile` и
  проверяет доступность файла сервисному пользователю; `local` читает
  переменную из `local.env`.
- Секреты, PEM и пользовательские regex-категории остаются на счётчиках —
  вне объёма. Команда офлайн-расшифровки (`unmask`) — вне объёма:
  расшифровка есть в пакете, CLI — отдельным изменением.

## Capabilities

### New Capabilities

- `mask-key`: ключ маскирования — источник, формат, проверка прав,
  генерация командой `gen-mask-key`, детерминированность и обратимость
  суррогатов IP и хостов по ключу.

### Modified Capabilities

- `request-masking`: требования к виду суррогатов IP и хостов и к
  стабильности таблицы уточняются для режима с ключом (публичные IPv4 — в
  `100.64.0.0/10`, хосты — `host-<шифртекст>.example`, одинаковость
  между процессами).
- `service-install`: установщик записывает путь к ключу маскирования в
  `EnvironmentFile` и проверяет права на него.
- `local-launcher`: ключ маскирования действует на локальном звене так же,
  как у `run`.

## Impact

- `internal/mask` — новый файл с ключом и шифрами (Feistel на AES для
  сетей и хостов, SIV-подобное шифрование имён), генератор суррогатов с
  ключом рядом с нынешним случайным; `surrogateScanner` учится узнавать
  `host-<base32>.example`.
- `internal/config` — `--mask-key-file`/`CLAUDE_PROXY_MASK_KEY_FILE`,
  чтение и проверка файла.
- `internal/server` — передача ключа в реестр, строка в стартовом логе.
- `internal/service` — строка в `envLines`, проверка доступа.
- `main.go` — подкоманда `gen-mask-key`.
- `docs/advanced.md` — раздел о ключе в «Маскировании», строка в таблице
  конфигурации.
- Зависимости: только стандартная библиотека (`crypto/aes`,
  `crypto/hmac`, `crypto/sha256`).
- Обратная совместимость: без ключа ничего не меняется. Смена ключа
  меняет все суррогаты — это ожидаемо.
