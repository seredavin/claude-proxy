Ветка `feature/add-keyed-masking` от актуального `main`; один PR, архив
в той же ветке.

## 1. Ключ (`internal/mask/key.go`)

- [x] 1.1 Тип `Key`: мастер-ключ и подключи D1 (`HMAC-SHA256(master,
  "claude-proxy/mask/v1/<назначение>")`), `Fingerprint()` — 8 hex
- [x] 1.2 `GenerateKey()` — 32 байта из `crypto/rand` в base64;
  `ParseKey(string)` — base64 с выравниванием и без, обрезка пробелов,
  ошибка с ожидаемой длиной
- [x] 1.3 `LoadKeyFile(path)`: проверка прав `mode & 077 == 0` (ошибка с
  `chmod 600 <путь>`), чтение, `ParseKey`, ошибки называют файл
- [x] 1.4 Тесты: разбор с `\n` и без выравнивания; 16 байт — ошибка с
  длиной; права 644 — ошибка с `chmod 600`; 600 — успех; отпечаток
  стабилен для фиксированного ключа и различается у разных ключей; два
  `GenerateKey` различаются

## 2. Перестановка малых доменов (`internal/mask/feistel.go`)

- [x] 2.1 Сеть Фейстеля D2: ширина 1..64 бит, 10 раундов, раундовая
  функция AES-256(подключ) от (раунд, ширина, домен, твик, половина),
  `encrypt`/`decrypt`
- [x] 2.2 Cycle walking на поддиапазоне с неподвижными точками (для хостов
  IPv4: домен 1..254, `0` и `255` на месте; IPv6: `0` на месте)
- [x] 2.3 Тесты: полный перебор 8, 12 и 16 бит — биекция и
  `Decrypt(Encrypt(x)) == x`; 56 и 64 бита — обратимость на 10 000
  случайных значений; разный твик — разная перестановка; «золотые»
  значения для фиксированного ключа

## 3. Суррогаты IP и хостов по ключу (`internal/mask/keyed.go`)

- [x] 3.1 Приватные IPv4 и ULA IPv6 по таблице D3: шифрование сети с
  твиком класса, хоста — с твиком реальной сети; `RevealIP` — обратный
  ход
- [x] 3.2 Публичные IPv4 → `100.64.0.0/10`, IPv6 → `2001:db8::/32` по D4:
  индекс сети из HMAC с номером пробы, пропуск занятых `usedNets`,
  хост — перестановкой
- [x] 3.3 Имена хостов по D5: нижний регистр, упаковка по основанию 40,
  SIV (HMAC-тег 8 байт + AES-CTR), base32 строчными без `=`, метки ≤63,
  `host-…example`; `RevealHost` с проверкой тега; длиннее 253 — сигнал
  вызывающему взять `host-N.example`
- [x] 3.4 Тесты: `10.20.30.40`/`.41` — одна `/24`, разные хосты, класс
  сохранён для всех трёх приватных диапазонов и ULA; `10.0.0.0` → `.0`;
  `RevealIP` восстанавливает приватные; публичный → `100.64.0.0/10`;
  искусственная коллизия сети → проба, суррогаты различны; хост:
  `Corp.Local`/`corp.local` → один суррогат, `RevealHost` → нижний
  регистр, чужой ключ — ошибка тега, длинное имя — метки ≤63 и валидный
  DNS, имя 240 символов — сигнал отката

## 4. Встраивание в реестр (`internal/mask/session.go`)

- [x] 4.1 `Options.Key`; `NewRegistry` передаёт ключ в сессии
- [x] 4.2 `surrogateFor`: для `ip`/`host` при ключе — keyed-генератор (D6),
  без повторных попыток и проверки совпадения с реальным значением;
  откат к `host-N.example` для слишком длинных имён с `Warn` без имени
- [x] 4.3 `surrogateScanner`: при ключе узнаёт
  `host-[a-z2-7]+(?:\.[a-z2-7]+)*\.example`
- [x] 4.4 Тесты: два `Registry` с одним ключом дают одинаковые суррогаты
  IP и хостов (перезапуск / два процесса); разные метки — один суррогат,
  но ответ `analytics` не демаскирует суррогат `dev-team`; адрес, которого
  нет в таблице, в ответе не трогается; SSE с keyed-суррогатом хоста,
  разрезанным между дельтами, восстанавливается; без ключа все прежние
  тесты проходят без изменений
