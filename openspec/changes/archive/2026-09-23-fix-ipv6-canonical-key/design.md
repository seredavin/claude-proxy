## Context

Ключ таблицы `forward` — текст совпадения; для хостов он приводится к
нижнему регистру (`surrogateLocked` и поиск в `maskText` при
`create=false`), для IP — нет. С ключом `keyedSurrogate` уже выдаёт один
суррогат на все записи (`sameValue` сравнивает адреса), без ключа каждая
запись получает новый случайный суррогат.

## Goals / Non-Goals

**Goals:** один адрес — один суррогат и одна запись таблицы, в обоих
режимах; одна функция ключа для записи и для поиска.

**Non-Goals:**
- Узнавание суррогата в другой записи в ответе модели (`2001:DB8:…`
  вместо `2001:db8:…`) — модель повторяет суррогат дословно; отдельная
  задача.
- Узнавание суррогата, вставленного пользователем в другой записи, при
  маскировании запроса.

## Decisions

### D1. Ключ таблицы — функция `tableKey(value, category)`

- хост — нижний регистр (как сейчас);
- IP — `netip.ParseAddr(value).String()`, если адрес не IPv4-mapped;
  IPv4-mapped и неразобранное — текст как есть.

`surrogateLocked` и поиск в `maskText` берут ключ только через неё.
Сейчас приведение хоста к нижнему регистру продублировано в обоих местах,
и расхождение между ними сломало бы перемаскирование ходов модели.

*Почему mapped как есть:* каноническая запись mapped-адреса точечная
(`::ffff:192.168.1.5`), и суррогат второй записи взял бы формат первой
(`::FFFF:…` для строчного исходника). Вложенный IPv4 и так даёт им один
суррогат с сохранением записи.

### D1a. Mapped на ходах модели — поиск по вложенному IPv4

На ходах модели (`create=false`) новых записей нет, поэтому
шестнадцатеричная mapped-запись, которой ещё не было в таблице
(`::FFFF:C0A8:0105` после `::ffff:c0a8:0105`), не находилась по ключу и
уходила открытым текстом. `lookupSurrogate` при промахе ищет суррогат
вложенного IPv4 и форматирует его в записи значения (`mappedSurrogate` —
та же функция, что при создании). Найдено на кросс-ревью; дыра была и до
изменения.

### D2. Обратная запись — первая встреченная форма

`reverse[sur]` уже пишется один раз, при создании записи; вторая форма
попадает в таблицу только через `forward`. Отдельного кода не нужно.

## Risks / Trade-offs

- [Ответ восстанавливается в записи первого появления: пользователь писал
  `fd00:0::1`, получил `FD00::1`] → тот же адрес; иначе пришлось бы
