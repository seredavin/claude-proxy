## Context

В v1.6.0 после авторизации шлюз выбирает URL и пропуск по метке
токена. `local` запускает Claude Code на loopback и передаёт клиенту
учётные данные для локального шлюза.

## Goals / Non-Goals

- Поддержать OpenAI по умолчанию и по метке в одном локальном процессе.
- Сохранить клиентский протокол Anthropic и совместимость цепочек.
- Автоматический failover, смена провайдера в текущей сессии и
  режим API-ключа OpenAI находятся вне этого изменения.

## Decisions

### Выбор провайдера после авторизации

Для общего OpenAI использовать `--openai-upstream профиль:модель`, для
маршрутов — `--openai-routes метка=профиль:модель`. Дублирующие настройки
маршрутов отклоняются. URL OpenAI фиксируется по официальному API. Параметры
цепочки Anthropic продолжают задаваться существующими флагами. Выбор
первого токена используется и в `local`, и в обработчике шлюза. Проверка
профиля и credential Anthropic выполняется для эффективного провайдера.
Прежний формат `профиль:модель` фиксирует модель на апстриме.
Формат `профиль:псевдоним=модель|псевдоним=модель` ограничивает выбор
заданными псевдонимами. `GET /v1/models` возвращает список выбранного
апстрима через Anthropic Models API. Для фильтра Claude Code
идентификатор получает префикс `claude-`, если в нём ещё нет `claude`
или `anthropic`. Отображаемое имя остаётся исходным псевдонимом. Поля `model` в Messages и
`count_tokens` разрешаются только в списке выбранного маршрута. Для
OpenAI в `local` включается обнаружение моделей шлюза.

### Локальный профиль и OAuth

Использовать публичный flow Sign in with ChatGPT для OSS с PKCE, state,
nonce, проверкой ID token и выданных scopes. Профиль живёт в каталоге
конфигурации пользователя. Хранить регистрацию, срок действия и токены
вместе, координировать обновление между параллельными процессами и
повторно загружать профиль после захвата блокировки. Проверять выдаваемое
согласие перед отправкой запросов. Для исходящих запросов создавать свои
заголовки и запрещать перенаправление credential. [Вход и регистрация](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

### Поток и история инструментов

Сохранять границу маскирования на стороне Anthropic, до преобразования
запроса и после преобразования ответа. Переводить историю и результаты
инструментов в `input`. Для подписки передавать полный контекст,
`store: false` и `stream: true`. Для обычного ответа собрать итоговое
сообщение из событий. Для SSE сопоставлять блоки по выходным индексам,
передавать частичные аргументы и завершать поток после итогового события.
Ошибки после начала SSE возвращать как события ошибки.
[Ограничения Responses API](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

### Собственный удалённый сервер

На сервере `run` использует профили из `<state-dir>/chatgpt`.
`install` сохраняет только назначения маршрутов. Профиль переносится
по SSH в стандартный ввод `chatgpt import` от имени пользователя сервиса.
Импорт создаёт отдельный стабильный идентификатор серверного хоста.
Сервер становится владельцем обновления перенесённого сеанса.
Локальный флаг `--upstream-chatgpt` указывает, что выбранный пропуск
внешнего звена ведёт на OpenAI. Для его метки локальное звено отправляет
только `X-Gateway-Key` и не требует токен Anthropic.
[Схема OpenAI для собственного сервера](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)

## Risks / Trade-offs

- Модель и доступ к подписке зависят от аккаунта. Использовать официальный
  список доступных моделей и диагностировать ошибки разрешения и квоты.
- У Claude Code есть блоки и инструменты без аналога в preview API.
  Покрыть текст и локальные function tools, проверить совместимость
  реальным интерактивным запуском и описать ограничения.
- Токенизация отличается между моделями. Проверить доступность
  официального счётчика для этого OAuth flow и описать оценку, если
  понадобится приближение.

## Migration Plan

Включение OpenAI требует явной настройки провайдера и локального входа.
Для возврата к цепочке Anthropic убрать назначение OpenAI и выбрать
существующую конфигурацию цепочки. Дельта `local-launcher` опирается на
актуальные требования v1.6.0 из `add-upstream-routes`. Перед архивированием
сверить обе дельты, чтобы сохранить требования к ключам маршрутов.
