## Context

В v1.7.0 `--upstream-chatgpt` позволяет запускать Claude Code через
внешний шлюз. Обновление OAuth выполняет процесс, у которого находится
профиль. В новой схеме этот процесс работает на клиентском компьютере,
а исходящие HTTPS-соединения к OpenAI открывает шлюз.

## Goals / Non-Goals

- Выпуск и сохранение профиля на клиенте, обновление после простоя и
  инференс через TLS-шлюз с существующим пропуском и списком моделей.
- Первичный браузерный вход на компьютере с доступом к OpenAI.
- SOCKS, CONNECT и произвольные OAuth-назначения не входят в изменение.

## Decisions

### Выбор режима

Сервер отмечает передачу клиентского OAuth через `@client:модель` или
`@client:псевдоним=модель|…` в существующих настройках OpenAI. Маркер
`@client` отличается от допустимых имён профилей и применим к общему
апстриму или маршруту. Режим требует `oauth` и TLS на удалённом шлюзе.
На ноутбуке `--upstream-chatgpt-profile` или
`CLAUDE_PROXY_UPSTREAM_CHATGPT_PROFILE` указывает локальный профиль и
включает поведение `--upstream-chatgpt`. Для выбранного апстрима
требуется HTTPS-адрес внешнего шлюза без URL-credentials, пути и query,
а также действующий пропуск на это звено.

### Запросы к модели

`local` выбирает маршрут по локальному токену, удаляет клиентские
credential Claude Code и подставляет полученный из профиля OpenAI
`Authorization: Bearer` перед передачей на внешний шлюз. Пропуск внешнего
шлюза остаётся в `X-Gateway-Key`. Сервер выбирает модель по маршруту и
использует Bearer этого запроса только для Responses API. Каталог моделей
и подсчёт токенов не требуют обращения в OpenAI.

### Обновление OAuth

Локальное хранилище повторно использует свой механизм блокировки и
атомарной записи. При истечении access token оно отправляет форму
обновления через `POST /_claude_proxy/chatgpt/refresh` на тот же шлюз.
У шлюза фиксированное назначение `https://auth.openai.com/api/accounts/oauth/token`.
Разрешён только `grant_type=refresh_token`. Шлюз принимает только
`client_id` и `refresh_token` и формирует официальный запрос с
фиксированным `resource`. Перенаправления запрещены. Обычный токен
Anthropic или токен серверного профиля не даёт доступа к этому endpoint.

Использовать отдельный обработчик до создания трассы и применения
маскирования. Применить малый лимит формы, таймаут, `Cache-Control:
no-store` и нормализованные ошибки. Транзитные секреты остаются в памяти
только во время обработки. При сетевой ошибке профиль остаётся
доступным для следующей попытки. При окончательном отказе обновления
пользователь получает указание на повторный вход.

## Risks / Trade-offs

- Шлюз видит оба токена в памяти, поэтому клиент должен доверять оператору
  и проверять TLS-сертификат. Доступ к обновлению привязан к маршруту.
- Одновременное обновление одной копии сеанса может инвалидировать токен.
  После переноса обновлением занимается выбранное устройство.
- При потере ответа после ротации может потребоваться повторный вход.
  Сбой передачи не превращается в автоматический переход на серверный профиль.

## Migration Plan

Получить профиль на машине с браузером и безопасно перенести его на
клиентский компьютер. Добавить новый маршрут с отдельным пропуском для
проверки, затем переключить клиент. После проверки оператор может вывести
из эксплуатации старый серверный маршрут и удалить его профиль.
