Ветка `feature/add-request-masking` от актуального `main`; один PR.
Архивация — процессный шаг после мержа, в задачах не числится.

## 1. Пакет `internal/mask`: правила и детекторы

- [x] 1.1 `rules.go`: `LoadRules(path)` — строчный разбор (`host`,
  `secret`, `regex <ИМЯ> <паттерн>`, `ip all|private|off`, `#`,
  пустые строки); ошибка с именем файла и номером строки; проверка имени
  regex-категории (`[A-Z0-9]+`) и компиляция RE2; `Rules.Summary()` для
  стартового лога (число правил по видам)
- [x] 1.2 `detect.go`: тип совпадения `(start, end, category, value)` и
  интерфейс детектора; слияние совпадений всех детекторов — сортировка,
  разрешение перекрытий leftmost-longest; признак «были отброшенные
  перекрытия» для повторной проходки (D3, не более трёх)
- [x] 1.3 Детектор IP: IPv4/IPv6 в тексте, с портом и CIDR; исключение
  loopback и неопределённого адреса; режим `private` по диапазонам
  `10/8`, `172.16/12`, `192.168/16`, `fc00::/7`; отсечение версий вида
  `1.2.3` и точечных последовательностей длиннее адреса
- [x] 1.4 Детектор хостов: точные имена и суффиксы `*.<домен>` из правил
  (включая сам домен), встроенный список непубличных TLD; без учёта
  регистра; границы токена — в URL, email, `host:port`; `localhost`
  исключён
- [x] 1.5 Детектор секретов: встроенные форматы (`sk-ant-`, `ghp_`/`gho_`/
  `github_pat_`, `AKIA`, `xox[abp]-`, JWT, PEM-блоки `BEGIN…PRIVATE
  KEY…END`), литералы `secret` (в любом контексте), regex-правила с первой
  группой захвата или всем совпадением
- [x] 1.6 Табличные тесты правил и детекторов по сценариям спеки:
  комментарии и пустые строки, пустой файл даёт только встроенные
  детекторы, ошибка с номером строки; подсеть, порт, префикс, loopback,
  `ip private`/`off`, суффикс домена, непубличный TLD, хост в URL и
  email, `ghp_`, литерал в середине слова, PEM целиком, перекрытие PEM и
  JWT, частичное перекрытие двух категорий с разным началом (остаток
  маскируется повторной проходкой)

## 2. Пакет `internal/mask`: таблица и суррогаты

- [x] 2.1 `session.go`: `Session` на метку — карты `real→surrogate`,
  `surrogate→real`, множество собственных префиксов суррогатов, счётчик,
  карта сетей; `sync.Mutex`; `Registry` с `map[label]*Session`
- [x] 2.2 Генерация суррогатов IP (D7): пул сетей по классу из
  `crypto/rand`, счётчик хостов `1..254`, переход на следующую сеть при
  исчерпании, публичные — три документационных `/24`, затем
  `100.64.0.0/10`; IPv6 через `2001:db8:R:R::/64`; при полном исчерпании
  класса — ошибка, а не повторный суррогат; сохранение порта и длины
  префикса при подстановке
- [x] 2.3 Генерация суррогатов хостов (`host-N.example`) и секретов
  (префикс + `MASKEDnnnn`, PEM с сохранёнными BEGIN/END, `SECRETnnnn`,
  `<ИМЯ>nnnn`); общий счётчик на метку
- [x] 2.4 Идемпотентность (D4): значение, уже являющееся суррогатом метки,
  не маскируется; коллизия детектора с существующим суррогатом — новый
  суррогат и `Warn`
- [x] 2.5 Debug-режим: при `Debug` `Session` пишет `mask`/`unmask` с
  `token`, `category`, `from`, `to` через переданный `slog.Logger`
- [x] 2.6 Тесты: стабильность суррогата между вызовами, биективность на
  тысяче значений, изоляция двух меток, идемпотентность, /24 сохраняется,
  публичный → документационный диапазон, переход в `100.64/10` после
  ~760 публичных адресов без повторов, `Debug` пишет пары, без `Debug`
  значений в логе нет

## 3. Пакет `internal/mask`: JSON запроса и ответа

- [x] 3.1 `walk.go`: обход `map[string]any`/`[]any` с ключом и родителем;
  пропуск ключей `model`, `type`, `role`, `id`, `tool_use_id`, `name`,
  `signature`, `media_type` и `data` при `type: base64`; режим
  forward-only для `messages[].role == "assistant"` и пропуск
  `redacted_thinking` (D5)
- [x] 3.2 `MaskRequest(body) (body, Stats, error)`: `json.Decoder` с
  `UseNumber`, обход с детекторами (user/system) или только по таблице
  (assistant), `json.Encoder` с `SetEscapeHTML(false)`; `Stats` — счётчики
  по категориям
- [x] 3.3 `UnmaskJSON(body) (body, int, error)` для не-SSE ответов: обход
  всех строк с заменой суррогатов leftmost-longest, IP-суррогат не перед
  цифрой; ошибка разбора возвращается вызывающему (тот отдаёт тело как
  есть)
- [x] 3.4 Тесты: system/tool_result/tool_use.input получают один суррогат,
  `tool_use_id` не тронут, base64 не сканируется, thinking с `8.8.8.8`
  байт в байт и `signature` тот же, возвращённое значение в истории
  перемаскируется, числа и `<>&` переживают round-trip, невалидный JSON —
  ошибка

## 4. Пакет `internal/mask`: SSE-поток

- [x] 4.1 `sse.go`: `UnmaskStream(io.ReadCloser) io.ReadCloser` —
  построчный разбор событий, `data:` как JSON, `event:`/`id:`/`retry:`/
  комментарии без изменений, `Close` прокидывается
- [x] 4.2 Дельты `text_delta`/`thinking_delta`/`input_json_delta`: замена
  в текстовом поле; в `partial_json` восстановленное значение
  JSON-экранируется; прочие события — через обходчик 3.3
- [x] 4.3 Удержание хвоста по префиксам (D8): на `index` блока хранится
  суффикс, являющийся собственным префиксом суррогата; приклеивается к
  следующей дельте того же блока; на `content_block_stop` отдаётся
  синтетическим `content_block_delta` того же типа
- [x] 4.4 Сброс всех хвостов синтетическими дельтами на `message_stop`,
  событии `error`, смене `index` без `stop`, EOF и в `Close()` — хвост
  не теряется ни при каком завершении
- [x] 4.5 Сбой разбора события — событие уходит как есть, `Warn` в лог,
  `unmask_errors++`; следующие события обрабатываются штатно
- [x] 4.6 Счётчики `unmasked` и `unmask_errors` для access-лога,
  доступные после закрытия потока
- [x] 4.7 Тесты: суррогат в `tool_use` `Bash` восстановлен, разрез между
  событиями (`host-1` | `.example`), разрез внутри IP перед цифрой,
  хвост на `content_block_stop`, хвост при EOF без `stop`, хвост при
  `error`, неизвестный суррогат не тронут, событие с невалидным `data:`
  проходит байт в байт и не ломает следующие, поток отдаёт первое событие
  до конца ввода (проверка через `io.Pipe`), `partial_json` с кавычкой в
  реальном значении остаётся валидным JSON

## 6. Сервер и шлюз

- [x] 6.1 `server.RunReady`: при `cfg.Mask != nil` — `mask.NewRegistry` с
  `Debug`/`Logger`, передача `Masker` и `MaskOnError` в `gateway.Options`;
  стартовый лог «маскирование включено» с `Summary()`; `Warn` о секретах
  в логе при `MaskDebug`
- [x] 6.2 `gateway.Options`: `Masker *mask.Registry`, `MaskOnError`;
  `Rewrite` удаляет `Accept-Encoding` при включённом маскировании (D2)
- [x] 6.3 `ServeHTTP`: после `authorize()` и `MaxBytesReader` — при
  включённом маскировании и непустом теле прочитать тело,
  `sess.MaskRequest`; успех — подменить `r.Body`, `r.ContentLength`;
  ошибка — `closed`: `400 invalid_request_error` «gateway could not mask
  request» без похода на апстрим, `open`: тело как есть и `Warn`
- [x] 6.4 `ModifyResponse`: `text/event-stream` → `UnmaskStream`;
  `application/json` → `UnmaskJSON` с пересчётом `Content-Length`, при
  ошибке разбора — тело как есть и `Warn`; прочие типы без изменений;
  сессия берётся по метке из контекста запроса
- [x] 6.5 `recorder`/`logAccess`: атрибуты `mask_<категория>`, `unmasked`,
  `unmask_errors` только при включённом маскировании и ненулевом
  значении; без значений
- [x] 6.6 Тесты шлюза с `httptest` апстримом: без `Masker` тело байт в
  байт; с `Masker` апстрим видит суррогат, а клиент — исходное значение
  в SSE; `count_tokens` маскируется; не-JSON тело → `400` при `closed`
  и проход при `open`; не-JSON ответ с `application/json` проходит как
  есть при `closed`; `Authorization` не тронут; две метки не видят
  суррогаты друг друга; `Accept-Encoding` не уходит апстриму; строка

- [x] 6.7 Тест цепочки: два шлюза с маскированием друг за другом —
  апстрим второго видит суррогат второго слоя, клиент первого получает
