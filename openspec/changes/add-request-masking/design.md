## Context

Мотивация — в proposal.md, требования — в `specs/request-masking/spec.md`
и дельтах `local-launcher`, `service-install`.

От чего отталкиваемся:

- `gateway.ServeHTTP` (`internal/gateway/gateway.go`) — `authorize()` даёт
  метку токена, затем `httputil.ReverseProxy` с `FlushInterval: -1`
  копирует запрос и ответ, не читая тела. `Rewrite` правит только
  заголовки. `ModifyResponse` не используется.
- Клиентский `Accept-Encoding` уходит апстриму как есть: если Anthropic
  ответит gzip, тело придёт сжатым, и `http.Transport` его не распакует
  (прозрачная распаковка работает только для заголовка, добавленного самим
  транспортом).
- `recorder` (`internal/gateway/log.go`) считает статус и байты для
  access-лога; заголовков и тел в логе нет умышленно.
- Конфигурация — `config.Raw` → `ApplyEnv` → `Config.validate()`; все
  небезопасные комбинации отвергаются на старте. `local` использует ту же
  `config.Raw`, поэтому новые флаги достаются ему автоматически.
- Зависимости — только stdlib и `golang.org/x/crypto`. YAML нет и не будет.
- Claude Code присылает на каждом ходу всю историю: `system` (CLAUDE.md,
  окружение, git status), `messages[]` с `text`, `tool_use`, `tool_result`,
  `thinking` (с `signature`), `tools[]`. Ответ — SSE с событиями
  `content_block_delta`, где `text_delta.text`, `input_json_delta.partial_json`,
  `thinking_delta.thinking` режутся по произвольным границам.

## Goals / Non-Goals

**Goals:**

- Ни одного нового внешнего модуля; вся логика маскирования — в отдельном
  пакете `internal/mask` без зависимости от `net/http`, тестируемом
  табличными тестами на строках.
- Прозрачность для клиента: SSE доходит по мере генерации, `tool_use`
  выполняется с настоящими значениями, JSON ответа семантически тот же.
- Без `--mask-rules` — нулевое изменение: ни чтения тела, ни новых
  аллокаций на пути запроса.
- Биективность таблицы на метку: одно значение ↔ один суррогат, никогда
  два значения на один суррогат.

**Non-Goals:**

- Персистентность таблицы между перезапусками (решено: память процесса).
- Маскирование заголовков, URL, query-строки.
- Маскирование не-JSON тел (multipart, бинарь) — с `closed` они отвергаются,
  с `open` проходят как есть.
- Автодетект «всех доменных имён» и публичных TLD.
- Изменение семантики `--max-body`: буферизация тела и так ограничена им.

## Decisions

### D1. Отдельный пакет `internal/mask`, шлюз лишь вызывает его

`mask` знает про правила, детекторы, таблицы и JSON/SSE-переписывание;
`gateway` — только про то, когда и с какой меткой их применить. Интерфейс:

```go
rules, err := mask.LoadRules(path)          // на старте, ошибки с номером строки
reg := mask.NewRegistry(rules, opts)         // opts: Debug bool, Logger
sess := reg.Session(label)                   // таблица метки, потокобезопасна
body, stats, err := sess.MaskRequest(body)   // []byte JSON → []byte JSON
rc := sess.UnmaskStream(resp.Body)           // io.ReadCloser для SSE
body, n := sess.UnmaskJSON(body)             // не-SSE ответ целиком
```

Альтернатива — размазать по `gateway`: короче сейчас, но пакет и так
самый нагруженный, а детекторы нужно тестировать без HTTP.

### D2. Точка врезки — `ServeHTTP` до `ReverseProxy`, ответ — через `ModifyResponse`

Запрос: после `authorize()` (метка известна) и `MaxBytesReader` тело
читается целиком, маскируется, подменяется `r.Body` + `r.ContentLength`.
Ответ: `ReverseProxy.ModifyResponse` заменяет `resp.Body` на
`UnmaskStream` для `text/event-stream` и на результат `UnmaskJSON` для
`application/json`; `Content-Length` у JSON пересчитывается, у SSE его
нет. Прочие типы не трогаются.

В `Rewrite` при включённом маскировании удаляется `Accept-Encoding`:
транспорт сам попросит gzip и прозрачно распакует, и `ModifyResponse`
всегда видит открытый текст. Цена — клиент не получит сжатый ответ; SSE
Anthropic и так не сжимает.

Альтернатива — свой `RoundTripper` поверх транспорта: даёт то же, но
дублирует то, что `ReverseProxy` уже умеет (`ModifyResponse`, flush).

### D3. Одна проходка по всем детекторам с разрешением перекрытий

Каждый детектор возвращает список совпадений `(start, end, category,
value)`; результаты сливаются, сортируются, при перекрытии остаётся
самое левое, при равном начале — самое длинное. Затем одна замена.

Почему не последовательные проходы: второй проход видел бы суррогаты
первого (суррогат IP — тоже IP), а PEM-блок содержит base64, похожий на
JWT. Одна проходка убирает класс ошибок «замаскировали маску».

Порядок приоритета при равном начале задаёт длина, поэтому PEM-блок
(самый длинный) всегда побеждает вложенные совпадения.

Частичное перекрытие с разным началом (проигравшее совпадение
выступает за границу победителя) — остаток проигравшего остался бы
незамаскированным. Поэтому, если при слиянии хоть одно совпадение было
отброшено из-за перекрытия, проходка повторяется по уже переписанному
тексту — не более трёх раз. Повтор безопасен благодаря D4: суррогаты
предыдущей проходки детекторы узнают и не трогают.

### D4. Идемпотентность: известный суррогат не маскируется заново

Перед созданием записи `MaskRequest` проверяет обратную таблицу: если
значение — уже выданный этой меткой суррогат, оно остаётся. Так
пользователь, вставивший в промпт кусок ответа модели, не запускает
цепочку «суррогат суррогата», и история остаётся согласованной.

### D5. Assistant-ходы и `thinking` — только по таблице (forward-only)

Для `messages[].role == "assistant"` обход строк применяет только замену
известных значений на их суррогаты (обратное к тому, что делал
`UnmaskStream`), без детекторов. Это ровно восстанавливает текст, который
модель сгенерировала и подписала: `signature` у `thinking` считается
Anthropic по тексту, любое отклонение — `400`. `redacted_thinking`
пропускается целиком.

Пользовательские роли и `system` — полный режим с детекторами.

### D6. Обход JSON: `map[string]any` + `UseNumber` + `SetEscapeHTML(false)`

Тело разбирается в дерево, строки переписываются на месте, дерево
сериализуется обратно. Порядок ключей меняется — для Anthropic и prompt
caching это несущественно (кэш строится по токенам промпта, не по байтам
JSON). `UseNumber` сохраняет числа как есть, `SetEscapeHTML(false)` не
портит `<`, `>`, `&` в коде.

Исключения по ключам (`model`, `type`, `role`, `id`, `tool_use_id`,
`name`, `signature`, `media_type`) и по контексту (`data` внутри объекта
с `type: base64`) реализованы в обходчике, который знает ключ и родителя.

Альтернатива — потоковый переписчик на `json.Decoder.Token()` с
сохранением порядка: меньше памяти, но заметно больше кода и своя
сериализация; выигрыш не окупается на телах в единицы мегабайт.

### D7. Суррогаты

- **IP**: на метку — карта «реальная /24 (v6: /64) → суррогатная /24».
  Суррогатная сеть берётся из пула того же класса: для `10/8` —
  `10.R.R/24`, `172.16/12` — `172.(16+R)/24`, `192.168/16` —
  `192.168.R/24`, публичные — `203.0.113/24`, `198.51.100/24`,
  `192.0.2/24`, а когда эти три сети заполнены — `100.64.R.R/24` из
  общего адресного пространства RFC 6598 (4 млн адресов, не маршрутизируется
  в интернете); IPv6 — `2001:db8:R:R::/64`. Хостовая часть — счётчик
  `1..254` в суррогатной сети; при исчерпании берётся следующая сеть того
  же класса. R — из `crypto/rand`, чтобы суррогаты не угадывались.
  Инвариант — биективность на метку: суррогат никогда не выдаётся
  повторно, при полном исчерпании класса `MaskRequest` возвращает ошибку
  (срабатывает политика сбоя). Сохранение /24 — best-effort: в один
  суррогатный /24 могут попасть адреса разных реальных сетей только у
  публичных адресов после первых ~760.
- **Хост**: `host-N.example`, N — счётчик метки. `.example` зарезервирован
  RFC 2606, не резолвится, не входит в список непубличных TLD — сам себя
  не заматчит.
- **Секрет**: встроенный формат — сохранённый префикс + `MASKED` +
  4-значный счётчик (`ghp_MASKED0001`, `AKIAMASKED0002`,
  `sk-ant-api03-MASKED0003`, `eyJ.MASKED0004`); PEM — строки BEGIN/END
  сохраняются, тело `MASKEDnnnn`; литерал — `SECRETnnnn`; regex —
  `<ИМЯ>nnnn`. Счётчик общий на все категории метки, чтобы суррогаты не
  совпадали между категориями.

Все суррогаты состоят из `[A-Za-z0-9.:_-]` — в JSON-строке им не нужно
экранирование, поэтому их можно искать в декодированном тексте дельты
и в `partial_json` одинаково.

### D8. Демаскирование SSE: разбор событий, удержание хвоста по префиксам

`UnmaskStream` читает поток построчно, собирает события (до пустой
строки), разбирает `data:` как JSON. Для `content_block_delta` с
`text_delta`/`thinking_delta`/`input_json_delta` берётся текстовое поле;
для остальных событий (`message_start`, `error`, …) — общий обходчик D6.

Разрез суррогата между событиями: на каждый `index` блока хранится
хвост — самый длинный суффикс текста, который является **собственным
префиксом** какого-либо суррогата метки (множество префиксов
поддерживается вместе с таблицей). Хвост не отправляется, а
приклеивается к началу следующей дельты того же блока; на
`content_block_stop` этого `index` хвост уходит отдельным синтетическим
`content_block_delta` того же типа перед `stop`. В типичном случае хвост
пуст и задержки нет.

Хвост никогда не теряется: на `message_stop`, на событии `error`, на EOF
и в `Close()` (клиент ушёл, апстрим оборвал соединение) все накопленные
хвосты всех блоков сбрасываются синтетическими дельтами — обрезанный
`Bash`-аргумент хуже, чем лишняя дельта после `error`. Дельта другого
`index` хвост не трогает: блоки в ответе идут последовательно, но
переключение индекса без `content_block_stop` тоже сбрасывает хвост
предыдущего блока.

Сбой разбора ответа (строка `data:` — не JSON, неожиданная структура,
не-JSON тело с `application/json`) обрабатывается всегда fail-open:
событие или тело уходит клиенту как есть, в лог — `Warn`, в счётчик
`unmask_errors` — единица. `--mask-on-error` на ответ не влияет: в этом
направлении утечки быть не может (худшее — клиент увидит суррогат), а
блокировать ответ Anthropic, за который уже заплачено, нечем оправдать.
Ошибка чтения из апстрима (обрыв) проходит через `ReverseProxy` как
прежде и не маскируется под сбой разбора.

Замена в тексте — по множеству суррогатов, leftmost-longest. Для
IP-суррогатов дополнительно требуется, чтобы следующий символ не был
цифрой (`10.7.3.9` не должен съесть `10.7.3.90`). В `partial_json`
восстановленное значение вставляется в JSON-экранированном виде (оно
стоит внутри строкового литерала фрагмента); в `text_delta` — как есть.

Событие после правки сериализуется обратно в `data: {...}`; строки
`event:`, `id:`, `retry:` и комментарии `:` проходят без изменений.

Альтернатива — байтовая замена по сырому потоку без разбора: проще, но
не видит суррогат, разрезанный границей событий, и не различает
`partial_json` от текста при экранировании.

### D9. Изоляция по метке, таблица — в памяти без вытеснения

`Registry` держит `map[label]*Session` под мьютексом; `Session` — две
карты (`real→surrogate`, `surrogate→real`), множество префиксов,
счётчики и карта сетей, всё под своим `sync.Mutex`. Вытеснения нет:
удаление записи ломает демаскирование продолжающейся сессии, а рост
таблицы ограничен количеством уникальных значений в истории — на
практике тысячи записей на команду. Размер отдаётся в стартовый лог и,
при желании, в `/healthz` позже.

### D10. Конфигурация и запуск: правила загружаются в `config.Resolve()`

`gateway.Options` собирается в одном месте — `server.RunReady()` из
`*config.Config`, и через него проходят оба пути: `run` (`main.go` →
`server.Run`) и `local` (`launcher.Run` → `server.RunReady`). Поэтому
носитель настроек маскирования — сам `config.Config`:

- `config.Raw`: `MaskRules` (путь), `MaskOnError` (`closed`|`open`, по
  умолчанию `closed`), `MaskDebug` (bool). Переменные
  `CLAUDE_PROXY_MASK_RULES`, `CLAUDE_PROXY_MASK_ON_ERROR`,
  `CLAUDE_PROXY_MASK_DEBUG`.
- `config.Config`: те же три поля плюс `Mask *mask.Rules` — результат
  `mask.LoadRules(MaskRules)`, который `Resolve()` вызывает после
  `validate()`. Ошибка файла (с номером строки) возвращается из
  `Resolve()`, то есть из `resolve()` в `main.go`/`local.go` — до занятия
  портов и до запуска `claude`. `config` получает импорт `mask` (у `mask`
  зависимостей нет, цикла не будет). Это единственное место, где `config`
  читает файл; принято сознательно, чтобы не дублировать загрузку в двух
  точках входа и не менять сигнатуры `server.Run`/`RunReady` и
  `launcher.Options`.
- `validate()` проверяет перечисление `MaskOnError` и что явно заданные
  `MaskDebug`/`MaskOnError` без `MaskRules` — ошибка (флаги без смысла).
- `server.RunReady()`: если `cfg.Mask != nil` — `mask.NewRegistry(cfg.Mask,
  mask.Options{Debug: cfg.MaskDebug, Logger: log})` и передача в
  `gateway.Options{Masker, MaskOnError}`; `nil` — выключено. Стартовый лог
  и `Warn` о debug-режиме — там же, рядом с логом слушателя.
- `launcher` и `planLocal` — без изменений: `Config` уже несёт всё нужное.
- `install`: `--mask-rules` и прочие попадают в `EnvironmentFile`;
  проверка доступности файла сервисному пользователю — тем же механизмом,
  что для `--key-file` (`internal/service/perm_unix.go`).

### D11. Наблюдаемость

`recorder` получает поле `mask mask.Stats` (карта `category→count` для
запроса, `unmasked` и `unmask_errors` для ответа); `logAccess` дописывает
их как атрибуты `mask_ip`, `mask_host`, `mask_secret`, `mask_<имя>`
(имя regex-категории в нижнем регистре), `unmasked`, `unmask_errors` —
только когда маскирование включено и значение ненулевое. Debug-режим — `Session` пишет через
`slog.Logger` записи `mask`/`unmask` с `token`, `category`, `from`, `to`;
на старте `main.go` печатает `Warn` о секретах в логе.

## Risks / Trade-offs

- [Суррогат совпал с настоящим значением, которое появится позже
  (реальный `10.7.3.9` в сети пользователя)] → случайный выбор сетей из
  `crypto/rand` делает совпадение маловероятным; при обнаружении (значение
  из детектора уже есть в обратной таблице) шлюз всё равно выдаёт новый
  суррогат и пишет `Warn` — демаскирование этого одного значения в
  ответах станет неоднозначным, это документируется.
- [Модель «дописывает» суррогат: `host-1.example` → `host-1.example.com`]
  → leftmost-longest по известным суррогатам восстановит `prod-db.corp.local.com`;
  это видимый артефакт, а не утечка; не лечим.
- [Ложные срабатывания IP-детектора на версиях `1.2.3.4`] → детектор
  требует, чтобы каждый октет был ≤ 255 и токен не был частью более
  длинной точечной последовательности; версии вида `v1.2.3` (три числа) не
  подходят под IPv4, а `1.2.3.4` — неизбежно, документируется как
  ограничение с обходом через `ip off` или `ip private`.
- [Задержка первого байта из-за удержания хвоста] → хвост удерживается
  только когда он — префикс известного суррогата; длина ограничена самым
  длинным суррогатом (~80 байт для PEM).
- [Порядок ключей JSON меняется, тело пересериализуется] → семантика та
  же; проверяется тестом на round-trip с `UseNumber`.
- [Клиент не получает gzip] → тела ответов Anthropic — SSE, сжатие там не
  использовалось; для `count_tokens` объём ничтожен.
- [`--mask-debug` пишет секреты в journal] → явный флаг, `Warn` на
  старте, раздел документации с предупреждением; `install` не включает
  его по умолчанию.
- [Память: тело запроса целиком + дерево JSON] → тело уже ограничено
  `--max-body`; дерево — кратно телу; для DMZ-шлюза с десятками
  одновременных запросов это десятки мегабайт, документируется.
- [Fail-closed ломает клиента при непредвиденном формате тела] →
  `--mask-on-error open` как аварийный выключатель без отключения
  маскирования целиком.
- [Маскирование включено на двух звеньях цепочки сразу] → работает как
  вложенные биекции: внешнее звено видит суррогаты внутреннего (IP-суррогат
  — тоже IP) и маскирует их ещё раз, на обратном пути каждое звено снимает
  свой слой. Корректно, но бессмысленно: наружу и так уходят суррогаты, а
  таблица внешнего звена растёт. Документация рекомендует одно звено —
  ближайшее к источнику; тест цепочки из двух шлюзов с масками на обоих
  подтверждает, что round-trip не ломается.

## Migration Plan

Функция выключена по умолчанию; существующие установки не меняют
поведения. Включение — добавить `CLAUDE_PROXY_MASK_RULES` в
`EnvironmentFile`/`local.env` и перезапустить. Откат — убрать переменную и
перезапустить; таблица в памяти исчезает вместе с процессом, история
Claude Code с суррогатами прошлого процесса продолжит работать (суррогаты
уйдут наружу как обычный текст).
