## Why

Внутреннее звено цепочки часто живёт на той же машине, что и Claude Code —
на ноутбуке разработчика, который ходит наружу через пограничный шлюз.
Сейчас такое звено обязано терминировать TLS: нужен `--domain`, каталог под
самоподписанную пару и `NODE_EXTRA_CA_CERTS` на клиенте — и всё это ради
соединения, которое не покидает loopback. Проверка сертификата на петле не
защищает ни от чего, а настройки добавляет заметно.

## What Changes

- Новое значение `--tls none` (`CLAUDE_PROXY_TLS=none`): шлюз слушает
  обычный HTTP без сертификата.
- Режим разрешён только на loopback-адресе (`127.0.0.1`, `::1`, `localhost`).
  При любом другом `--listen`, включая `:9443` без хоста, шлюз отказывается
  стартовать: открытым текстом по сети ушли бы пропуски и токены подписки.
- В режиме `none` не требуются `--domain`, `--state-dir`, `--cert-file`,
  `--key-file`; ACME-слушатель не поднимается. Заданный `--domain`
  игнорируется.
- Апстрим по-прежнему только `https://`: plain-режим касается входящей
  стороны, наружу открытым текстом шлюз не ходит.
- `client-env` для такого шлюза печатает `ANTHROPIC_BASE_URL=http://<listen>`;
  доверие к сертификату на клиенте не нужно.
- `install` принимает `--tls none`: проверка `/healthz` после запуска идёт
  по `http`.
- Стартовый лог сообщает, что слушатель без TLS.
- Документация: `docs/advanced.md` — четвёртый источник в разделе
  «Источники сертификата», пример локального звена на ноутбуке в разделе
  «Цепочка шлюзов»; таблица конфигурации.

## Capabilities

### New Capabilities

- `plain-listener`: слушатель без TLS — когда допустим, что требует и чего
  не требует, как выглядит клиентская настройка.

### Modified Capabilities

- `gateway-chaining`: внутренним звеном цепочки может быть шлюз без TLS на
  loopback; требование `https` к апстриму при этом сохраняется.

## Impact

- `internal/config` — новое значение `TLSSource`, валидация loopback,
  ослабление требований к `--domain`/`--state-dir` для `none`.
- `internal/tlsconf` — `New` возвращает провайдер без `tls.Config` для
  `none` (или сервер обходит провайдер).
- `internal/server` — `Serve` вместо `ServeTLS`, когда TLS нет.
- `internal/clientenv` — схема и хост базового URL зависят от режима.
- `internal/service` — `waitHealthy` по `http` для `none`.
- `main.go` — текст справки для `--tls`.
- `docs/advanced.md`, `README.md` (ссылка на сценарий), `scripts/chain-smoke.sh`
  (опционально — прогон с plain-звеном).
- Обратная совместимость: существующие значения `auto`/`files`/`self` и их
  валидация не меняются; поведение по умолчанию (`auto`) прежнее.
