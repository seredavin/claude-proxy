## Purpose

Слушатель без TLS для шлюза, который живёт на одной машине с клиентами:
когда соединение не покидает loopback, сертификат ничего не защищает и
только усложняет настройку.

## ADDED Requirements

### Requirement: Источник сертификата `none` — слушатель без TLS

Шлюз SHALL поддерживать источник сертификата `none`, при котором клиентский
слушатель принимает обычный HTTP. В этом режиме шлюз SHALL НЕ требовать
имени шлюза, каталога состояния и файлов сертификата и SHALL НЕ поднимать
слушатель проверки ACME. Проверка пропуска и проксирование SHALL работать
так же, как при TLS.

#### Scenario: Запрос по HTTP проксируется

- **WHEN** шлюз запущен с источником `none` на loopback-адресе, и клиент по
  `http://` присылает запрос с верным пропуском
- **THEN** запрос уходит на апстрим, а клиент получает ответ апстрима

#### Scenario: Имя шлюза и каталог состояния не нужны

- **WHEN** шлюз запускают с источником `none`, не задавая ни имени шлюза,
  ни каталога состояния, ни файлов сертификата
- **THEN** шлюз стартует

#### Scenario: Неверный пропуск отвергается и без TLS

- **WHEN** шлюз запущен с источником `none`, и клиент присылает запрос без
  пропуска или с неверным
- **THEN** клиент получает `401`, запрос на апстрим не уходит

### Requirement: Слушатель без TLS допустим только на loopback

С источником `none` шлюз SHALL стартовать только если адрес слушателя —
loopback: `127.0.0.1`, `::1` или `localhost`. Адрес без хоста (все
интерфейсы) или любой другой адрес SHALL приводить к отказу на старте с
объяснением: открытым текстом по сети уходили бы пропуски и токены подписки.

#### Scenario: Loopback-адрес принимается

- **WHEN** источник `none` и адрес слушателя `127.0.0.1:9443`, `[::1]:9443`
  или `localhost:9443`
- **THEN** шлюз стартует

#### Scenario: Адрес без хоста отвергается

- **WHEN** источник `none` и адрес слушателя `:9443`
- **THEN** шлюз не стартует, ошибка называет режим `none` и требует
  loopback-адрес

#### Scenario: Внешний адрес отвергается

- **WHEN** источник `none` и адрес слушателя `0.0.0.0:9443` или
  `10.0.0.5:9443`
- **THEN** шлюз не стартует с той же ошибкой

### Requirement: Апстрим остаётся только `https`

Источник `none` SHALL касаться только входящей стороны. Требование к
апстриму быть `https://` SHALL сохраняться без исключений.

#### Scenario: Апстрим по `http` отвергается и в режиме `none`

- **WHEN** источник `none`, а апстрим задан как `http://...`
- **THEN** шлюз не стартует с ошибкой о схеме апстрима

### Requirement: Клиентская настройка для слушателя без TLS

Команда печати клиентских переменных SHALL для источника `none` выдавать
базовый URL со схемой `http://` и хостом слушателя, с портом. Остальные
переменные SHALL совпадать с TLS-вариантом того же режима.

#### Scenario: Базовый URL по `http`

- **WHEN** шлюз настроен с источником `none` и адресом `127.0.0.1:9443`
- **THEN** напечатано `ANTHROPIC_BASE_URL=http://127.0.0.1:9443`

### Requirement: Отсутствие TLS видно на старте

Шлюз SHALL сообщать в стартовом логе, что слушатель работает без TLS.

#### Scenario: Стартовая запись

- **WHEN** шлюз стартует с источником `none`
- **THEN** запись о запуске содержит указание на слушатель без TLS

### Requirement: Установка сервиса со слушателем без TLS

Установщик SHALL принимать источник `none` и проверять готовность шлюза
после запуска по `http`.

#### Scenario: Проверка здоровья по `http`

- **WHEN** сервис устанавливают с источником `none`
- **THEN** установщик дожидается ответа `/healthz` по `http://` и сообщает
  об успехе
