# openai-chatgpt-upstream Specification

## Purpose
Даёт Claude Code доступ к моделям OpenAI по подписке ChatGPT через
локальный шлюз с выбором провайдера по метке токена.
## Requirements
### Requirement: Вход ChatGPT выполняется на ноутбуке

Прокси SHALL использовать официальный Sign in with ChatGPT через браузер
и loopback callback. Каждый профиль SHALL храниться отдельно с правами
0600, а обновление токенов SHALL сохраняться атомарно. Для запросов SHALL
использоваться согласие на ChatGPT plan usage. Токены SHALL передаваться
только официальным конечным точкам, которым они предназначены, и SHALL
быть исключены из окружения Claude Code, логов и трассы.

#### Scenario: Вход и повторный запуск

- **WHEN** пользователь завершил вход и дал разрешение на использование плана
- **THEN** следующий локальный запуск использует сохранённый профиль

#### Scenario: Истекло время жизни токена

- **WHEN** действующий профиль содержит истёкший access token
- **THEN** прокси обновляет его перед запросом, а при отзыве разрешения
  просит повторно войти

### Requirement: Провайдер и модель выбираются для каждого апстрима

Конфигурация SHALL позволять независимо назначать OpenAI общему апстриму
и маршруту по метке. OpenAI SHALL требовать указания профиля ChatGPT и
модели. Конфигурация OpenAI SHALL работать в `run`, systemd и `local`.
Метка без маршрута SHALL выбирать общий апстрим. Ошибка провайдера SHALL
возвращаться клиенту через выбранный маршрут.

#### Scenario: OpenAI по умолчанию

- **WHEN** общий апстрим использует OpenAI и у метки нет маршрута
- **THEN** запрос уходит в OpenAI с заданной моделью и профилем

#### Scenario: OpenAI только для маршрута

- **WHEN** общий апстрим ведёт в цепочку Anthropic, а метка имеет маршрут OpenAI
- **THEN** запросы этой метки идут в OpenAI, остальные используют общий апстрим

#### Scenario: Удалённый сервер использует импортированный профиль

- **WHEN** пользователь завершил вход на ноутбуке, перенёс профиль по SSH
  и запустил удалённый шлюз с назначением OpenAI на метку
- **THEN** сервер выбирает профиль по этой метке, сам обновляет OAuth
  токен и обращается к OpenAI. Запросы по остальным меткам идут в Anthropic

#### Scenario: Профиль отсутствует на сервере

- **WHEN** клиент предъявляет токен маршрута OpenAI, для которого нет профиля
- **THEN** только запросы к этому апстриму получают ошибку доступности профиля

### Requirement: Адаптация протокола Claude Code

Прокси SHALL принимать текст, системные инструкции, схемы инструментов,
вызовы и результаты инструментов из Anthropic Messages и переводить их
в Responses API. Он SHALL возвращать Anthropic-совместимые обычные
ответы и SSE, включая причины остановки, идентификаторы инструментов и
доступные счётчики использования. Для `count_tokens` SHALL возвращаться
совместимый ответ с документированной точностью. Неподдерживаемые блоки
SHALL приводить к явной ошибке. Действующие правила маскирования и
демаскирования SHALL применяться к содержимому маршрута OpenAI.

#### Scenario: Claude Code выполняет инструмент и продолжает запрос

- **WHEN** OpenAI передаёт аргументы инструмента частями, а Claude Code
  затем отправляет его результат
- **THEN** Claude Code получает один вызов с полными аргументами, а OpenAI
  получает историю и результат с тем же идентификатором

#### Scenario: OpenAI отклоняет запрос из-за лимита

- **WHEN** OpenAI отвечает ограничением плана
- **THEN** Claude Code получает совместимую ошибку лимита без повтора
  через другой апстрим

### Requirement: Псевдонимы моделей OpenAI доступны через шлюз

Для общего апстрима OpenAI и каждого маршрута OpenAI SHALL настраиваться
собственный список соответствий клиентского идентификатора модели модели
OpenAI. Для выбранного апстрима `GET /v1/models` SHALL возвращать только
его клиентские идентификаторы. Они SHALL проходить фильтр меню Claude
Code, сохраняя исходные псевдонимы как отображаемые имена. Messages и
`count_tokens` SHALL принимать идентификаторы каталога и исходные псевдонимы и отклонять неизвестные без обращения в OpenAI.
Прежняя конфигурация с фиксированной моделью SHALL сохранять семантику.
При запуске через OpenAI локальное звено SHALL включать обнаружение моделей
Claude Code для локального и внешнего маршрута.

#### Scenario: Смена модели по одному токену

- **WHEN** клиент с одним токеном запрашивает список моделей и выбирает
  последовательно два разрешённых идентификатора
- **THEN** каждый запрос отправляется в соответствующую модель OpenAI
  на том же апстриме

#### Scenario: Попытка вызвать модель за пределами списка

- **WHEN** клиент выбирает модель, разрешённую только на другом маршруте
- **THEN** шлюз отвечает ошибкой 400 без обращения в OpenAI
